# Smart Watchdog：教保機構再犯風險預警

## 一句話

給教育局稽查承辦一張「下一季最該去看的園所排名」，排名由**再犯風險模型**產生，
並用**負責人／委辦法人連坐**擴充監控名單；每個分數都能點開看理由。

## 目標對映命題三項效益

| 命題效益 | 本系統的可量化定義 | 驗收 |
|---|---|---|
| 提升風險辨識率 | 時間切分回測的 AUC 與 PR-AUC | 必須**優於兩個 baseline**：隨機、以及「按歷史裁罰次數排序」的簡單規則 |
| 縮短預警時間 | 每次裁罰後即刻重算分數，預測未來 12 個月再犯 | 對每筆實際發生的再犯，系統在多少天前就已列入前 N 名（中位提前天數） |
| 降低人力負擔 | 前 N 名覆蓋率：只看前 N 園，能抓到後續 12 個月多少比例的裁罰 | 前 100 名覆蓋率 vs 隨機抽 100 園 vs 按次數排前 100 |

## 角色

- **稽查承辦**：幼教科負責排稽查與訪視的人。主要使用者。
- **科長／局端主管**：要看整體風險分布與人力配置依據，不看單園細節。
- **資料維護者**：我們（黑客松團隊），負責更新資料與重訓。
- **評審**：看 demo 與 deck，會問「憑什麼」。

## User Stories

### US-1：全市風險排名

**As a** 稽查承辦
**I want to** 看到新北全部園所依「未來 12 個月再犯風險」排序的清單，可按行政區、立案別、風險等級篩選
**So that** 我能決定下一季先去哪幾家

**Acceptance Criteria:**
- [ ] Given 資料已更新，when 開啟排名頁，then 顯示 1,216 園的分數（0–100）、風險等級（高／中／低）、最近一次裁罰日期、裁罰次數、負責人、類型、行政區
- [ ] Given 選了行政區「新莊區」與立案別「私立」，when 套用篩選，then 清單只剩符合條件的園，且排序維持
- [ ] Given 一家園所從未被裁罰且不在任何連坐名單，when 看它的分數，then 顯示「無紀錄」，**不排名、不出屬性分**（autoplan E3），只列弱訊號命中數
- [ ] Given 資料日期超過 90 天，when 開啟頁面，then 頁首顯示「資料截至 YYYY-MM-DD」並以警示色標示
- [ ] Given 頁面載入，when 分數計算尚未完成或 DB 缺表，then 顯示明確錯誤與「重新計算」入口，不顯示空白表

### US-2：園所詳情與分數理由

**As a** 稽查承辦
**I want to** 點開一家園所看它的分數怎麼來（裁罰時間軸、各特徵貢獻、連坐來源）
**So that** 我能向科長說明為什麼排它，而不是「AI 說的」

**Acceptance Criteria:**
- [ ] Given 一家有裁罰紀錄的園，when 開啟詳情，then 看到裁罰時間軸（日期、法條、處分、行為人角色），以及分數的前 5 項特徵貢獻（正負方向）
- [ ] Given 該園被連坐納入監控，when 開啟詳情，then 顯示連坐來源（哪位負責人／哪個法人、哪家園、哪筆裁罰）
- [ ] Given 該園是非營利園且有財報，when 開啟詳情，then 顯示財務燈號（人事費率、每核定名額收入、流動比、負債比）與同法人其他園的比較；沒有財報則此區隱藏、不顯示空值
- [ ] Given 行為人姓名，when 顯示於任何頁面，then 只顯示角色（負責人／教保人員），姓名不出現在畫面與匯出檔

### US-3：負責人／委辦法人關聯圖與連坐名單

**As a** 稽查承辦
**I want to** 看到某位負責人或委辦法人名下所有園所，以及其中哪些已被裁罰
**So that** 一家出事時我能一次把相關園所列入監控

**Acceptance Criteria:**
- [ ] Given 一位負責人名下有 ≥2 園，when 開啟關聯圖，then 以圖呈現負責人節點與各園節點，被裁罰的園以顏色標示，邊上標裁罰次數
- [ ] Given 非營利園，when 建立關聯，then 勾稽單位是園名括號內的委辦法人，不是 owner 欄（owner 為法人代表）
- [ ] Given 負責人名下任一園在觀察期內被裁罰，when 重算名單，then 名下其他園進入「連坐監控」名單並標示來源；連坐**不改變**模型分數，只加旗標
- [ ] Given 負責人欄為空（財團法人附設園常見），when 建立關聯，then 該園不掛任何負責人節點，並在資料品質頁計數
- [ ] Given 同名不同人風險，when 兩園負責人同名但分屬不同法人／地址相距甚遠，then 仍連結但標示「同名待人工確認」

### US-4：模型回測與效益儀表

**As a** 科長／評審
**I want to** 看到模型在歷史資料上的回測結果與三個 baseline 的比較
**So that** 我知道這個排名比「憑經驗」或「看誰被罰最多次」好多少

**Acceptance Criteria:**
- [ ] Given 觀察點為每筆裁罰日期（裁罰後起算），when 回測，then 訓練只用觀察點之前的資料，標籤為觀察點後 12 個月內是否再犯；報告 AUC、PR-AUC、前 50／100／200 名覆蓋率
- [ ] Given 同一回測，when 比較，then 並列三條 baseline：隨機、按歷史裁罰次數排序、按最近一次裁罰距今排序
- [ ] Given 模型不優於「按次數排序」baseline，when 呈現，then 儀表如實顯示，不隱藏；deck 改以規則為主
- [ ] Given 每筆實際再犯，when 計算提前天數，then 顯示中位數與分布（該園在再犯前幾天首次進入前 100）
- [ ] Given 回測，when 分年展示，then 每個觀察年（2019–2025）各自報告，避免單一年份主導

### US-5：稽查名單匯出

**As a** 稽查承辦
**I want to** 把前 N 名（含連坐名單）匯出成 CSV／Excel
**So that** 排稽查行程時能直接用

**Acceptance Criteria:**
- [ ] Given 目前篩選條件，when 按匯出，then 產生含園名、行政區、類型、分數、等級、連坐旗標、最近裁罰日期、裁罰次數的檔案，欄名為中文
- [ ] Given 匯出檔，when 檢查，then 不含行為人姓名與負責人姓名（負責人以匿名代碼呈現）
- [ ] Given 沒有符合篩選的園，when 按匯出，then 提示「無資料」，不產生空檔

### US-6：資料更新與重算

**As a** 資料維護者
**I want to** 一個指令重抓公開資料、重跑 OCR（僅新增檔）、重建 DB、重訓模型、重算分數
**So that** 資料過期時能在一小時內更新

**Acceptance Criteria:**
- [ ] Given 執行更新指令，when 完成，then 記錄每個階段的筆數、耗時、失敗數到 log，並更新「資料截至」日期
- [ ] Given 某來源（如全國教保資訊網）抓取失敗，when 更新，then 其他階段照常執行，該來源沿用上次資料並在資料品質頁標示
- [ ] Given OCR 已有輸出的檔案，when 重跑，then 跳過不重做
- [ ] Given 重訓後 AUC 較上一版下降超過 0.05，when 完成，then 不自動切換分數版本，並警示

### US-7：整體風險分布（主管視圖）

**As a** 科長
**I want to** 看一頁總覽：各行政區高風險園數、各立案別裁罰率、本季新增裁罰、連坐名單規模
**So that** 我能決定人力怎麼分配到各區

**Acceptance Criteria:**
- [ ] Given 開啟總覽，when 載入，then 顯示行政區地圖或長條（高風險園數）、立案別裁罰率、近 12 個月裁罰趨勢、監控名單總數
- [ ] Given 點擊某行政區，when 進入，then 跳到 US-1 清單並套用該區篩選
- [ ] Given 頁面，when 顯示任何數字，then 旁邊標示資料截至日期

### US-8：稽查人力排程（autoplan E1，Peter 指示）

**As a** 稽查承辦
**I want to** 輸入稽查員人數與每人每週訪視數，得到一份本季「週 × 稽查員」的訪視行程與預計覆蓋率
**So that** 我知道這季跑得完哪些園、少跑幾趟能多抓幾家

**Acceptance Criteria:**
- [ ] Given 設定 N 人 × v 次/週 × 13 週，when 產生排程，then 20 秒內回傳行程，每園至多一次，總席次 ≤ N·v·13，顯示覆蓋率（前 C 園覆蓋後續 12 個月裁罰 %）與 vs 按次數／隨機
- [ ] Given 本季名單有園，when 產生，then 名單園必在行程內；承辦釘選為固定、排除為移除
- [ ] Given 容量 0 或不可行，when 產生，then 422 顯示原因與「放寬」建議，不顯示空表
- [ ] Given 求解逾時，when 回傳，then 標「近似解」
- [ ] Given 分數換批，when 開啟排程頁，then 舊排程標 stale 並提示重排
- [ ] Given 停辦園，when 排程，then 不出現

### US-9：本季名單

**As a** 稽查承辦
**I want to** 一個名單頁：每園一行備註，狀態 草稿 → 送核 → 核定
**So that** 交給科長時有憑有據

**Acceptance Criteria:**
- [ ] Given 從排名加入的園，when 開名單頁，then 依風險排序、可寫備註、可移除
- [ ] Given 名單為空，when 開頁，then 「尚未加入任何園」+ 去排名入口

### US-10：自然語言問答（唯讀 agentic）

**As a** 稽查承辦或科長
**I want to** 在右側抽屜用中文問「新莊區近半年被罰兩次以上的園」「為什麼 X 排第一」「這季為什麼沒排 Y」
**So that** 不用學篩選器也能對名單追問

**Acceptance Criteria:**
- [ ] Given 一個問題，when 送出，then 串流回答固定三段：可展開的工具呼叫／數字表／「帶我去」深連結；每輪存 `agent_turns`
- [ ] Given 問題要求姓名、寫入、或非 SELECT，when 送出，then 拒答並列可問範例；系統無任何寫入工具
- [ ] Given 無 Anthropic key 或 LLM 429，when 開抽屜，then 顯示「未設定／稍後再試」，其餘功能 100% 可用
- [ ] Given demo，when 問預備的三題，then 離線快取秒回

## 非功能

- 全部本機可跑：SQLite + Python + 前端靜態頁或輕量 server；無外部付費服務。
- 隱私：行為人姓名只存 DB、不出畫面與匯出；demo 用假名代碼。
- 可解釋：每個分數必附前 5 特徵貢獻；規則（連坐）與模型分開呈現。
- 可重現：`build_db.py` 與訓練腳本固定 seed，回測結果可用一指令重跑。
